## Label classes

Every labelled record carries `label_class`, `label_source`, `label_method`, `label_protocol` (`provisional_automated_labeling_v1`), `human_verified` and `label_provenance` (`evaluation/data_preparation/label_classes.py`).

| Class | Meaning | Binary label | `Example.label_method` |
|---|---|---|---|
| VERIFIED_CORRECT | Benchmark gold answer, matched to the raw source by deterministic checks | correct | `independent_ground_truth` |
| SYNTHETIC_INCORRECT | Generated by a recorded deterministic transformation of the gold answer; never human verified | incorrect | `synthetic_transformation` |
| HUMAN_VERIFIED_INCORRECT | Requires a human review record; the code refuses it otherwise. **0 exist.** | incorrect | `independent_human` |
| UNRESOLVED | Not decidable under the protocol; kept separate, never relabelled, excluded from binary metrics | none | none |

The game layer keeps synthetic labels visible downstream:
- `Example` accepts `label_method="synthetic_transformation"` for incorrect answers only, and exposes `label_class`.
- `ReadinessReport.label_composition` gives per-role class counts.
- `ComparisonResult.label_composition` and `PolicyEvaluation.label_composition` give the class counts of the scored examples.
- `final_test_workflow readiness` reports `final_test_label_basis` (synthetic vs human-verified negatives per benchmark) and `final_test_negatives_synthetic_only`.

## Negative generation (`synthetic_negatives_v1`)

`evaluation/data_preparation/synthetic_negatives.py` contains pure functions: the same inputs always give the same candidate.

- **GSM8K:** the first of gold+1, gold−1 and gold+2 whose answer is not already in the group, keeping the gold's number format. A result that would flip a nonnegative gold to negative is skipped. Each negative records two quality flags: `how_many_question` and `rounding_or_ratio_cue_present`.
- **HotpotQA**, in order:
  1. yes/no complement;
  2. for comparison questions, the other compared entity (the other supporting-fact title);
  3. increment the first number in the gold;
  4. a non-supporting context paragraph title that does not overlap the gold or the question, chosen by minimum SHA-256 of `group|title`.

Gold answers, context, supporting facts and source IDs are preserved on the labelled records.

**Avoiding class-revealing metadata.**
- Candidate IDs are opaque hashes of namespace, group and normalized answer (`rx1-…` for exploratory, `ft2-…` for Final Test v2).
- Candidates are sorted by ID within each group.
- Verifier-input and roster files contain no label, gold, supporting-fact, generation or source-candidate fields, and every row has exactly the same keys for both classes.

## Limitations of synthetic labels

- **Not natural errors.** Synthetic negatives are rule-generated near-misses, not real model mistakes. False-acceptance rates measured on them may differ from rates on real incorrect answers.
- **GSM8K pairwise signal.** Every v2 GSM8K negative is gold+1, so within a group the larger number is the incorrect candidate. Verifiers judge one candidate at a time, but any method that compares a group's candidates could exploit this. Exploratory Development mixes gold+1 and gold−1.
- **GSM8K label risk.** Gold+1 is incorrect under exact GSM8K answer semantics. 52 v2 questions (and 63 new exploratory negatives) have rounding or ratio cues where a neighbouring value might be defensible. The flags are recorded so analyses can stratify on them.
- **HotpotQA format signal.** Distractor titles are entity names that can differ in answer type from the gold. Mean answer length is 16.3 characters for SYNTHETIC_INCORRECT vs 14.8 for VERIFIED_CORRECT (v2), and initial capital 79% vs 66%. See `class_format_audit.json` and the exploratory `audit.json`.
- **HotpotQA negatives inside the evidence.** A distractor title appears in the evidence context by construction, so evidence-matching verifiers could find it "supported".
- **Benchmark gold is trusted.** VERIFIED_CORRECT means the benchmark gold, not a human-checked answer. Benchmark label noise carries over.
- **Custody is not independent.** The dataset creator is the designated custodian. The labels sit in a Git-ignored directory of the same workspace, and there is no operating-system protection. Verifier developers and Development experiment runners are refused by the label gate. Evaluation authorization remains pending.
- **Exploratory only.** No human approved the rules, the GSM8K train source, or the 300-group cap. Results on these datasets are exploratory and must report the synthetic label basis.
