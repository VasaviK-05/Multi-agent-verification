# Candidate-answer construction and audit protocol

## Evaluation unit and gold provenance

The unit is a `(dataset version, original question/claim ID, candidate answer)` tuple. Preserve the original dataset ID and version. Record candidate ID/index, exact candidate string, source, construction method, label, label provenance, reviewer/adjudication, permitted context identity, evidence-resource identity, and any skip reason. Keep all candidates for one question in one related-example group.

Gold labels must originate from benchmark annotations or a documented independent adjudication. A construction flag such as `expected_correct: false` is not independent verification. Any manual adjudication must record rubric/version, reviewer identifiers or roles, independent decisions, disagreement resolution, date, and final rationale without replacing source fields.

## Correct candidates

- **GSM8K:** use the benchmark answer extracted from its `####` final-answer field. Preserve the full worked solution as label provenance if permitted, but do not provide it to the verifier unless all methods are explicitly in a reference-assisted condition. Compare answer equivalence using an approved numeric/unit normalization rule, not string equality alone.
- **HotpotQA:** use the benchmark answer as the canonical correct candidate. Preserve answer aliases or adjudication only when independently sourced and versioned. The question's own context is permitted only in the declared reference-assisted condition.
- **FEVER:** the original claim plus its SUPPORTS/REFUTES/NOT ENOUGH INFO label is a claim-verification example, not a fabricated yes/no answer pair. Keep the three labels distinct. In particular, NOT ENOUGH INFO means the dataset does not supply enough evidence to determine truth; it is not an incorrect answer.

## Incorrect candidates

Incorrect candidates must be generated by a documented method and then independently checked against the question and its gold source. Store the proposed method separately from adjudicated correctness.

- The current GSM8K `gold + 1` negative is synthetic and may be used only after validating answer semantics, units, and ambiguity under a predeclared rubric. Do not present the synthetic label itself as independent ground truth.
- The current HotpotQA cross-example answer is a proposed negative only. Check against the question, supplied reference context, accepted aliases, and any independently permitted source. Coincidental correctness or ambiguity makes the item unresolved, not automatically incorrect.
- Do not create FEVER negative answers by mapping NOT ENOUGH INFO to false. SUPPORTS and REFUTES express claim status; NOT ENOUGH INFO stays a distinct evidence insufficiency label.

## Independent verification and insufficient evidence

Use reviewers or an independently defined validation process that does not see system predictions. Require agreement or a documented adjudication rule; preserve unresolved cases with an explicit label state and reason. For evidence-dependent labels, record whether sufficient permitted evidence was present. When it is absent, classify as evidence-insufficient/unresolved under the approved protocol; do not call the candidate incorrect merely because the configured corpus failed to retrieve support. Report evidence-absent questions separately.

If any reference text is supplied to a verifier, label that condition **reference-assisted**. Give all comparison methods the same text and retrieval budget. Do not mix a dataset-provided paragraph condition with a shared-corpus condition in one aggregate without stratification.

## Direct arithmetic and word problems

GSM8K is a word-problem dataset. The current project does not contain a verified direct-arithmetic subset marker. If direct arithmetic questions are studied separately, create a Development-time annotation rubric (for example, whether the question supplies an explicit closed expression without narrative reasoning), annotate before evaluation, measure reviewer agreement, and keep those groups distinct from general word problems. Do not infer the subset from the rule verifier's success or failure, and do not use final-test performance to select its definition.

## Required record fields and exclusions

At minimum preserve `dataset`, `dataset_version`, `source_split`, `original_id`, `group_id`, `question`, `candidate_answer`, `gold_label`, `label_provenance`, `candidate_source`, `adjudication_status`, `reference_context`, `evidence_resource_id`, and `skip_reason`. Keep original source metadata unchanged alongside normalized fields. Any excluded item remains in an audit ledger with its stable ID and reason.
