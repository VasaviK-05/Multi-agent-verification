## Ordered rosters for Person 2 cost collection and Experiment 4

Both ordered rosters contain every eligible candidate. Groups are sorted by `SHA-256(salt + group_id)` within each benchmark, then GSM8K and HotpotQA groups alternate. All candidates of a group are adjacent and share a `group_rank`. The ordering uses only identifiers, never labels or outcomes.

- Person 2 salt: `research_v1/person2_cost_collection_order/v1`
- Live-runtime salt: `research_v1/live_runtime_validation_order/v1`

Any approved size *N* is taken as "all rows with `group_rank ≤ N`". That keeps groups whole and benchmarks balanced by group count. For example, the first 50 groups give 62 candidates (GSM8K 37, HotpotQA 25), the first 100 give 123, and the first 200 give 245. **No size is chosen here.** Person 1 has not run any cost collection, and none may run until the adapter configuration exists and Person 2 approves the roster size.
