# Frozen-policy transfer evaluation under a declared current collector

This is an additive **evaluation contract**, not a source-equivalence exception,
new fitting objective or deployment policy. `evaluate`/`audit-collector` retain
strict historical semantics. `evaluate-transfer` requires an explicit
`frozen_policy_evaluation_transfer_v1` declaration and **fresh paired clean and
altered development recordings** from the same identified current collector.

## Why transfer is needed, and what it means

Original arithmetic/factual recordings name Git revision
`17b695373f935dc1f5fd09c37cf8917969367f7a` but application digest
`47597967da7d8f05aa56ef1ed6fbd544eb70e607aaf8804e5163e650cea35e4d`.
The previous audit established that neither the commit's tracked application tree
nor the inspected source exports reproduce that digest. There is no new recovery
lead; completed searches were not repeated. Authentic source evidence remains
unavailable, which is different from establishing equivalence.

Strict reproduction still needs the exact missing source snapshot/environment.
Transfer does **not** need or claim it. It applies the unchanged frozen decision
rule to newly observed verifier reports under a separately declared implementation.
Historical/current collector equivalence is explicitly **not established**.
Model-free contract probes do not change that statement.

The report separates `historical_clean` (retained reference), `current_clean`
(fresh new implementation baseline) and each current altered scenario. Only
**current clean versus current altered** is the paired intervention comparison.
Historical versus current changes are confounded by source, environment, model or
other declared baseline-resource differences and must not be attributed solely to
poisoning. All actual resource deltas are recorded. Between the fresh paired
conditions only the existing declared corpus/index/configuration-path intervention
is permitted: implementation/model/service changes and mixed sources reject.
Stochastic verifier variation and unmeasured host load remain limitations.

The original artifact bytes, IDs, all strategies/probabilities (including zero),
history reputation, dependencies, thresholds, loss settings, estimated costs,
budget and contributor/coverage/failure semantics are unchanged. Current reports
do not update reputation. The original certificate is checked only for its
original fitted matrix. Retained historical clean cells/coverage are replay-checked
against that matrix as a supported-decision-semantics check, not proof of full
historical collector equivalence. Poisoned coverage need not meet the old clean
coverage floor. No optimizer, sampling, replacement policy or rebinding is used.

## Exact input contracts

`app.game.offline.upstream_transfer` exposes:

- `EvaluationTransferDeclaration`: version `frozen_policy_evaluation_transfer_v1`;
  original artifact ID; historical scientific recording ID/setup fingerprint;
  actual `current_clean_setup: MeasurementSetup`; new clean request ID; sorted
  unique `(app/relative.py, actual_sha256)` source manifest whose content ID must
  equal the new application digest; original decision-semantics ID; fixed existing
  vote-adapter report contract; new authority, implementation-change,
  report-compatibility and archived-source references; every changed historical/
  current resource fingerprint. Required literal declarations are
  `equivalence=not_established_original_source_unavailable`,
  `scope=original_prepared_development_examples_only`, and
  `historical_clean_use=separate_reference_never_new_clean_substitution`.
- `FreshDevelopmentRecording(bundle, evidence_validation)`: complete labelled
  pilot/study, development **only**, expected setup exactly observed, all candidate
  outcomes, actual pre/post observations, measurements and retained failures.
  No unexecuted returned reports, smoke/diagnostic promotion or historical reuse.
- `FrozenPolicyTransferInput(declaration, artifact, historical_clean,
  current_clean, report_attacks, scenarios)`: original artifact/certificate and
  exact historical training binding; new clean setup/request matches declaration;
  questions, candidate answers, reference text, independent labels/provenance,
  grouping, datasets, analysis, capabilities, prerequisites, factory and randomness
  controls match original development inputs (only execution IDs/authority/setup
  change). Each `ScenarioRecording` must fully match the fresh clean scope and
  source/environment, with its own new IDs and declared altered resources.
- `evaluate_frozen_transfer(inputs) -> FrozenPolicyTransferEvaluation`, version
  `frozen_policy_transfer_development_v1`, role
  `prepared_development_frozen_rule_transfer_only`.

The declaration requires explicit compatibility review; it does not certify new
algorithm accuracy. Changed score-meaning strings/authoritative decision interfaces
and unknown report adapter contracts reject. Existing report parsing, identities,
normalization and resource-bound Evidence readiness probes still apply. A verifier
with no established historical returned-report interface cannot acquire a new one
silently in v1. The current builtin capability registry must accept the original
roster. Initial transfer keeps logical resource topology (verifier/kind/resource ID
keys) fixed; content differences are explicit. New verifiers, resource-sharing
topology, pooled contexts, changed decision semantics or expanded question scope
need separate reviewed contracts, not settings that disable these checks.

Empirical Evidence-bearing **current clean and altered** setups each need their
own seven-case `EvidenceValidation` bound to actual resources. Neither historical
proof nor new clean proof can stand in for altered proof. No final-test reports,
labels or payload paths are accepted; only the original reservation metadata.
For these two prototypes the scope is the original 20 development groups / 40
candidate answers per task, reference-assisted, within their prepared question
identities. Semantic-comparison diagnostics are not added to the prototype.

Schema: `EvaluationTransferDeclaration.model_json_schema()` and
`FrozenPolicyTransferInput.model_json_schema()`. Real configurations/labels/source
snapshots stay private under ignored `build/`; do not commit them.

## Output, ownership and remaining readiness

`transfer-evaluation.json` contains original policy IDs, probabilities, strategy
definitions, reputation/threshold/minimum/units, original certificate scope, all
historical/new collector setups, declaration ID and
`historical_current_equivalence_established=false`. Separate condition metrics
report errors/counts, coverage, uncertainty, selective risk (`null` if undefined),
validation loss, frozen configured cost diagnostics, failures and per-strategy
reasons/outcomes. `timing` preserves ordered attempt IDs, execution flags,
durations and timing status (including failures), execution/unavailability counts
and observed executed-duration sums. These are attempt times, not request latency,
money, recalibrated costs or efficiency-improvement evidence. Retain source bundles
for full reports, observations and failure text; the report binds their scientific
identities. Changed timings do not rewrite the frozen policy.

Study owner approves the transfer interpretation, exact current implementation,
replacements, controls, budgets, report compatibility and rehearsal. Dataset owner
supplies original artifact/recordings, unchanged independent development labels,
references and metadata-only reservation. Resource owner supplies installed local
models, clean/altered corpus/index receipts and actual compatible observations.
Collection owner snapshots/freezes actual current source/environment, executes
bounded fresh paired calls and audits checkpoints/proofs. Our evaluator verifies
contracts and scores the frozen rule only; it supplies no source-equivalence proof,
verifier repair, automatic poisoning detector, deployed protection or immunity.

No new real preflights, approvals, altered resources, paired recordings or Evidence
proofs have been supplied/executed by this implementation. Therefore a real run is
**not ready yet**, although the new transfer contract no longer requires recovery
of the unavailable historical source. There is no implicit source bridge or runtime
compatibility relaxation. Synthetic checks establish implementation behavior only;
