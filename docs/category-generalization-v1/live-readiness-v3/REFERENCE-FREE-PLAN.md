This supersedes the earlier v2 Rule-only proposal as the default design recommendation. Rule-only is a resource-minimal possible experiment, not an optimality conclusion. No new policy has been fitted, no reference-free native reports collected, and no weights/resources rebuilt or changed.

Define an opt-in `reference_free_addition_v1` contract, initially bounded two-operand integer addition (e.g. operands in [-10000,10000]), supported existing anchored grammar, numeric-only candidate, absent context. Use offline independent labels only for evaluation; never attach them as request context. Rule computes the answer itself. No analyzer/selector/verifier implementation edit is needed to represent absence. The new compatibility ID must differ from the historical reference-present artifact; keep the old rejection intact.
2. Preserve the full declared candidate capability roster with Semantic explicitly excluded for missing reference. Enumerate every subset and both aggregations with the existing implementation. Freeze source, dependency/reputation and actual resource/coverage/execution contracts. Do not copy the old empirical evaluation bindings, reliability matrix, singleton authorization or probabilities to a new artifact. Pin a new manifest covering actual resources used by all feasible teams, and a newly reviewed resource-observation/binding adapter. No teammate-owned implementation changes are proposed.
3. Obtain separately approved existing Evidence/Confidence resources and explicit generation/collection budgets if those teams are to compete. Use history-only measurements to set/freeze proposed attempt costs and budget before development fitting. Keep the diagnostic historical-cost table above as a comparison, not fabricated measurements. If costs make a team infeasible, record the budget reason; do not choose a budget to force the desired winner. If resources cannot be supplied, stop the broad comparison or explicitly approve a narrower contract first.
4. Independently collect reference-absent native reports under that newly pinned contract. Preserve existing empirical payoff construction and finalization for all feasible team/aggregation rows and clean/adversarial columns, then use the existing minimax machinery (and reliability-first constraints if adopted and preregistered) without fixing a favorite row or probabilities. Cost/coverage/dominance shortcuts need proven assumptions; do not infer them from this smoke. Fit once per class, not per question.
5. Freeze policy, evaluation and acceptance protocol before untouched evaluation. Only then add a separately reviewed opt-in scope/resource factory for its new IDs. Existing factory helpers reject unapproved new artifacts; do not weaken those guards. Preserve exact-first historical routes. Supporting reference-free requests for already registered exact strings would require a backend-owned explicitly versioned request/runtime namespace with unchanged legacy defaults, not silent override.

## Independent data and bounded collection proposal — NOT authorized

Use disjoint operand-pair groups, grouping commutative pairs and wording variants within a split. Initial pilot proposal: 32 history groups, 32 development groups and 64 untouched held-out groups; two candidates per group, one independently correct and one independently incorrect. Include negative/zero operands, cancellation, repeated operands, boundary values, different digit lengths, unseen pairs and accepted grammar variants. Historical questions and their pair families must not leak into held-out groups. Choose group sizes and label proportions before collection; this pilot is not a sufficient sample-size proof for a strict population false-accept target.

Independent ground truth should use a separately reviewed integer/Fraction oracle and auditable labels, not Rule outputs, verifier agreement or model generations. Context remains None in every runtime input. Wrong candidates include sign and off-by-one errors, carry/cancellation mistakes and independently labeled plausible alternatives. Add separately budgeted malformed/unsupported-input fixtures: invalid numeric answers, multiple expressions, instructions appended to a matched prefix, out-of-scope operations and unexpected reference context. Unsupported questions should route unavailable rather than be scored as factual rejects. No fixtures are generated or collected by this plan.

With three eligible verifiers each evaluated once on each of 256 pilot candidate cases, upper bound is **768 native attempts** (256 each Rule/Evidence/Confidence) and **1280 Ollama generations** at five samples per Confidence attempt. Split counts: history 192 attempts/320 generations, development 192/320, held-out 384/640. Aggregation/team evaluation can reuse the same authorized per-example collected reports if the recording protocol preserves the dependencies and execution/failure semantics required by the empirical pipeline; never fabricate missing cells or treat unavailable execution as a successful report. Independent repeated-generation or timing studies would require extra authorization beyond these numbers.

Original estimates sum to 21218.736560014077 ms per full three-verifier case, about 5432 seconds for 256 cases, excluding model loading/service overhead. Five 60-second generation timeouts per case alone can reach 76800 seconds overall. These are planning bounds, not measured runtime or a monetary quote. Freeze a separately approved outer wall/attempt/generation/service-metadata limit and no-retry journal protocol after reviewing resource startup. The current two-Rule-attempt authorization covers NONE of this proposed collection.

Develop an attack manifest independently of held-out outcomes: predefined per-verifier failures/abstentions and joint correlated perturbations under a symmetric, documented threat model, plus clean data. Do not design adversaries to favor Rule or tune them using held-out results. Reconstruct payoffs from actual finalized correct accept/reject, false accept/reject, uncertainty/unresolved outcomes and measured costs, using identical labels/loss weights across strategies. Archive complete strategy definitions, matrices, solver certificates and probabilities with new IDs. Freeze history priors, contributor/group dependencies, thresholds, coverage/reliability targets, loss and cost weights and resource manifests before development evaluation/fitting; no held-out tuning.

Held-out evaluation must report candidate and group counts, correct accepts/rejects, false accepts/rejects, uncertainty, achieved capability coverage, decision coverage, weighted decision loss, attempt/generation counts, per-verifier and end-to-end measured costs and uncertainty intervals accounting for grouped examples. Compare the fitted mixture against Rule-only and other declared baselines without giving them an unfairly different budget or failure treatment. Predeclare numeric thresholds and sample size from the desired false-accept bound/confidence level before collecting data; zero observed errors is not zero population error. Report partial cells, interruptions and failed provenance instead of omitting them. Independent source/label custody and untouched held-out access are required before research-certification claims.

No native collection, fitting, historical artifact modification, backend activation, merge or deployment is part of this plan.
