# Category generalization v1 — preparation only

No category is newly scientifically certified by this change. No native inference,
new fitting, threshold changes, historical artifact rewrites or default activation
are performed. Existing dirty/untracked research work is preserved.

The additive `app.game.category_applicability` module offers explicit operator
registration of frozen atomic artifacts with versioned scope declarations. It
checks exact artifact/task identity, evaluated team coverage, distinct development
and held-out report identities, required scenario declarations and semantic
contradiction declarations before delegating to the existing router. It does not
verify report contents, authenticate reviewers, establish split independence or
prove performance. A declaration must never be treated as automated certification.
The existing low-level router remains unchanged and is not a certification API.

## Inspected implementation boundaries

| Verifier | Existing capability | Required restriction | New certification |
|---|---|---|---|
| Rule | `arithmetic` in selector descriptors | Only actual Rule parser/check implementations; other deterministic checks do not imply new selector capabilities | Incomplete |
| Evidence | `direct_fact`, `evidence_retrieval` | Frozen corpus/index, retrieval/NLI configuration and provenance; execution evidence/coverage gates | Incomplete |
| Semantic | `semantic_comparison` | External non-label reference, original model/mode/thresholds; similarity is not factual equivalence | Incomplete |
| Confidence | `consistency` | Frozen provider/model/sampling/prompts, readiness, costs and shared dependencies | Incomplete |
| Combinations | Existing feasible strategy enumeration | Exact frozen context, policy, resources, team completeness and informative coverage | Incomplete |

`strategies.enumerate_strategies` already enumerates all nonempty eligible subsets
and both aggregations. Four eligible candidates permit up to 30 strategies before
budget, participant and coverage exclusions. A category need not use every subset.
The declaration lists teams evaluated, not teams forced into positive policy mass.
Minimax probabilities, empirical matrices and LP formulation are unchanged.

## Separately versioned fitting and evaluation workflow

Prepare `category_policy_study_v1` manifests separately from frozen studies:

1. Specify each actual supported question grammar/distribution, exclusions,
   analyzer/scoring identity, domain, difficulty, reference presence, resources,
   costs, budget, participant/contributor minima and dependency/reputation snapshot.
   Confidence eligibility must require consistency capability, not factual coverage.
2. Audit historical fitting/evaluation distributions against that exact scope.
   Exact-question studies are insufficient evidence of category applicability.
   Record reuse justification or mark a fresh fit required, per category and team.
3. Reserve independent history, development and untouched held-out groups before
   collection; audit exact and semantic-family overlap. Do not manufacture
   independence by renaming examples. Seal held-out labels and record custody.
4. On development data only, use existing recording, payoff construction and
   minimax fitting paths. Freeze artifacts, strategy definitions, probability
   vectors, resource identities, applicability and analysis rules before holdout.
5. Evaluate all feasible teams/aggregations, best development-selected pure team,
   best feasible single verifier, uniform feasible mixture and existing heuristic
   under equal budgets and identical resource/abstention rules. Separate policies
   for different task identities/budgets; no category-to-team hardcoding.
6. Include correct, incorrect, uncertain, unsupported, missing evidence/reference,
   resource unavailable, timeout/failure and insufficient-informative-contributor
   cases. Test complete-team execution and absence of fallback/early termination.
7. Semantic challenge families: changed numbers (`12` versus `21`), negation
   (`is` versus `is not`), entities (`Paris` versus `Rome`), and relationships
   (`Earth orbits Sun` versus `Sun orbits Earth`). Record routing eligibility,
   actual score/decision, public outcome and contradiction label separately.
   A high similarity on a contradiction is a verifier limitation, not a routing
   failure. Injected-vector tests cannot establish native semantic accuracy.
8. Publish per-category/team coverage, abstention, false accept/reject, uncertainty,
   failure, cost and baseline comparison reports with limitations. Install reviewed
   declarations only for distributions supported by those reports.

## Bounded execution plan requiring separate approval

Before any native run, produce an enumerated example manifest and exact resource
lock plus per-verifier call/token/time/cost ceilings. Suggested *upper bound* for
an initial development pilot: 4 categories x 10 examples x 4 verifier attempts =
160 attempts, with ineligible attempts skipped and recorded. This is a ceiling,
not a scientifically sufficient sample or an approved run. Set explicit numeric
wall-time/token/monetary ceilings using the deployed provider contract before
requesting approval. No holdout is consumed in the pilot; no retry beyond the
approved ceiling. Use pilot costs to propose a separate fitting/held-out campaign.

## Outstanding acceptance evidence

Unseen-question native reachability and scientific category applicability remain
unproven for all four verifiers and combinations. Full end-to-end certification,
independent dataset preparation, native semantic contradiction observations,
resource-failure evaluation and strong-baseline comparisons remain outstanding.
Routing/declaration unit tests alone do not satisfy those acceptance criteria.
