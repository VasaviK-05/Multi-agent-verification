## Complete roster and original attempt records

The proposed global captured candidate set is confidence/evidence/rule/semantic. Every example has exactly one terminal outcome per captured name: 774 × 4 = 3,096 outcome slots if the full proposed scope is approved. With GSM8K reference null and HotpotQA references valid, semantic is ineligible on 374 GSM8K examples: 2,722 expected calls and 374 explicit unexecuted unavailable outcomes. This count is conditional on no other eligibility exclusions. Preserve registration, capability descriptor, prerequisites and exclusion reasons. Semantic requires a nonblank non-judgment-list reference; unknown readiness is not proof of availability. Evidence does not require user reference. Do not initialize prerequisite-less Semantic with an eager reference-assisted factory; Tabmayee must provide an appropriate factory.

For each slot persist CollectedAttempt.attempt_id, example_id, run_id, candidate, canonical planning_json; nested Attempt.verifier_name, state, execution_id, configuration_id, adapter, report_provenance, observed_resources_json and report_json. Request run_id maps to Example.validation_id and Attempt.execution_id. Derive attempt identity using the existing attempt_identity function: content_id(['offline_attempt_v1', request_id, run_id, verifier_name]); freeze run identities before dispatch. Map adapter names exactly to confidence_v1/evidence_v1/rule_v1/semantic_v1. Preserve original serializable returned_payload_json separately from canonical report_json, including all metadata and reasoning. Do not normalize a corrupted report in place.

States are directional (support or rejection retained by report.passed/decision), abstention, unavailable, failed, missing. Directional and abstention require a valid VerificationResult report; unavailable/failed/missing prohibit one. An abstention is a returned report normalized by vote_normalization, not an absent attempt. Timeout is failed plus timing_status timeout and explicit exception provenance. Unavailable before dispatch is executed=false with null duration and timing_status. Every executed call has nonnegative duration_ms, timing_status returned/failure/timeout/interrupted, linked measurement, observed resources before/after and exact setup/verifier/input hashes. Interrupted or malformed/missing records remain incomplete and cannot enter replay. Preserve issues, achieved_capabilities, errors, and failure categories; unexpected exception handling must be reviewed for runtime parity.

Persist model/prompt/service/corpus/index/source/config fingerprints and exact adapter/normalization implementation identity, execution configuration, setup fingerprint, dependency/library/hardware identities. Public resource hashes are in source-resource-summary.json; complete original resource-compatibility.json is retained locally. Record receipt identity and reference availability even for unavailable rows. Original rehearsal report_json fields contain escaped JSON strings; do not silently repair or transplant them into the new dataset.

## Acceptance gates (all mandatory)

1. Completeness: exact approved roster hash; one terminal outcome for every example × candidate pair; no duplicates, extra IDs, missing attempts, unapproved calls or unresolved issues. Require eligible calls to be executed or explicitly failed/unavailable with cause. A terminal failure may complete collection but does not establish informative coverage or scientific usability.
2. Provenance: 100% links among approved input hash, request_id, run_id, attempt_id, configuration_id, setup/resource fingerprints and raw payload. Reject changed source/question/answer/reference bytes or resources. Independent labels and custody approvals must be verifiable before empirical export.
3. Replay: validate RecordingBundle links/completeness and actual Example/Attempt models in a compatible offline environment. `Example` needs domain, planning_category, validation_id, independent labels and complete_team_independent_v1; planning_category is category_id(approved PlanningContext), not a benchmark string. Deferred context binding at export is allowed; do not require fitted probabilities to collect raw reports. `replay` requires candidate set equality and rejects any missing state. `TrainingManifest` takes History/Development plus an outcome-free reservation; do not build DatasetManifest with held-out outcomes.
4. Groups: all candidates of each approved related group stay together; question maps to one group; no ID/question/group/content/run overlap across History/Development or custodian reservation. Check original source keys and runtime content keys. Paragraph/supporting-fact overlap already reported by source audit needs explicit scientific disposition. “Group” does not prove independence.
5. Safe restart: freeze request/setup and IDs; durable pre-dispatch start intent, durable completion acknowledgment before advancing; atomic snapshots and metadata; preserve old journal and resume into a new directory. Reject duplicate identities, torn records and changed setup; quarantine ambiguous started-without-completion calls for manual disposition. Never retry them automatically or claim exactly-once effects. Retain both original and recovery/checkpoint IDs and durable storage receipts. Test crashes before dispatch, after dispatch, before/after completion persistence using prebuilt records and fake sinks only.
6. Team independence: fix q/a/reference, order, randomness/reset and resource conditions independently of selected strategy. No reputation feedback, team/prefix conditioning, early termination, fallback team, attacks or policy sampling during recording. Owners attest cache_contract with synthetic/read-only checks; if reports depend on team/order/prefix beyond controlled randomness, ordinary cached replay is invalid and requires a redesigned protocol.

## Current durability implementation and acceptance limits

Package A's game-owned file_journal.py and collector wiring are the single implementation. Durable pre-dispatch starts, durable completion acknowledgment, atomic metadata/snapshots and strict duplicate/torn/in-flight recovery are locally implemented. collection.py appends each new result only after sink acknowledgment. Tests use deterministic synthetic adapters and temporary files; no empirical reports are collected.

See filesystem-support.md for the tested local macOS/APFS contract. Current engineering test outcomes are recorded in final-review.md; they do not certify the actual collection host. Windows, other POSIX hosts/network filesystems and physical power-loss behavior remain unverified or unsupported as specified. External rehearsal runners must adopt the same interface if selected; they are not changed here. File recording is independent of PostgreSQL.

The historical flush-only findings are preserved in archive/package-a/recording-durability-assessment.md and archive/package-b/recording-contract.md. They are not current implementation status. New source bytes and a new test environment do not reproduce the historical calibration setup; actual collection remains blocked pending scientific/custody/resource/platform approval and explicit authorization.
