# Verbatim offline question contract

Diagnosis: 18 Development candidates /9 HotpotQA groups have leading/trailing question whitespace; 36 History candidates /18 groups have the same characteristic. No answer outer whitespace was found. JSON serialization preserves the characters; collector construction does not strip them. The conflict was the generic Text -> identifier validator used for question content, not an unsupported verifier input. Application ValidationRequest already accepts nonempty strings without requiring stripped content.

Technical change `verbatim_question_text_v1`: game-owned PreparationExample.question and replay Example.question use StrictStr plus a nonblank-content validator. Non-string and empty/whitespace-only questions still fail. Identifiers retain the existing stripped/nonblank validator. Labels, provenance, source/resource checks, request authorization, reference prerequisites and allowed purpose literals are unchanged. No app/models, analyzer or verifier implementation is modified.

This is an additive acceptance expansion at the offline boundary, not a transform or encoding adapter. Valid existing question strings and their IDs/hashes are unchanged. New accepted outer whitespace participates in canonical content identity and exact verifier dispatch. No trimming, sentinel insertion, Unicode normalization or surrogate hashing occurs. Source byte hashes remain distinct from canonical parsed-tuple hashes. Tests parse/serialize/reload all 18 actual permitted Development tuples with synthetic schema-only labels; those fixture labels are not study ground truth. Synthetic dispatch tests verify the same content reaches the test adapter.

The code supports lossless inputs; it does not approve the research population/reference/label estimand. Old cost hashes for 24 disputed timing rows still require actual producer call-input/transform custody. Accepting raw questions now cannot certify what historical calls received. No retrospective normalization or equivalence is inferred.

Interface ownership: both changed schemas are app/game/offline and belong to the game owner. No teammate interface patch is required. Review this precise acceptance expansion with the feature branch. A future study request must identify this source/profile, keep raw question and candidate answer strings, and retain all IDs and actual runtime tuple hashes. No runnable real-data request is emitted in this task.
